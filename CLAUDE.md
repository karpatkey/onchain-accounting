## What this repo is

Onchain accounting infrastructure for portfolio NAV: **balances** (per-protocol position adapters), **prices** (Chainlink + custom feeds), **NAV** (`NAVCalculator` aggregates the two), and **bridge** (escrow + per-protocol bridge adapters). No tokenized share or sub/redeem logic lives here — that sits in a separate layer above NAV and the bridge.

`NAVCalculator` is UUPS-upgradeable. Balance and price adapters are deployed standalone (not proxied) — each is immutable post-deploy, with one **documented mutable-cache exception**: the **assisted balance-adapter family** (`src/balances/AssistedBalanceAdapters/`) — `NexusMutualStakingPoolsAssistedBalanceAdapter`, `EtherFiWithdrawalQueueAssistedBalanceAdapter`, `StakeWiseV3ExitQueueAssistedBalanceAdapter` — each keeps a per-account cache of position *coordinates only* (**never amounts**), values every position from live on-chain reads, and re-verifies ownership on every read, so a caller can only under-report, never over-report. **In production the cache is also *complete*, so "under-report only" understates the guarantee: the portfolio Safes' roles-modifier allow-list permits these protocol entries ONLY through the assistant contracts (the direct entrypoint is not allow-listed), so a position of these types cannot be active without having been fed.** That half is enforced **outside this repo** — nothing here does it, since the mutators are permissionless; the residual risk is a roles-permission change adding a non-assistant path, which this repo has no tripwire for. The cache mutators are **permissionless** (`msg.sender`-keyed, no roles) and fed on-chain by a delegatecall `BalanceAdapterAssistant` (the owner Safe delegatecalls it, so the adapter sees `msg.sender = Safe = owner`) — see [ADR 0015](docs/decisions/0015-assisted-balance-adapter-family.md) and [ADR 0018](docs/decisions/0018-assistant-fed-assisted-balance-adapters.md). (A **second** documented mutable-cache exception is the **attested balance-adapter family** (`src/balances/AttestedBalanceAdapters/`, [ADR 0022](docs/decisions/0022-attested-balance-adapter-family.md)) — currently just `MerklRewardsAttestedBalanceAdapter`: it caches a **proof-verified amount** rather than coordinates, because Merkl allocations live off-chain and cannot be valued live. It is fed permissionlessly by an off-chain agent that **upserts** proven `(account, token)` entries on-behalf-of; integrity rests on the on-chain merkle proof against the live Merkl root + stale-root→0, so it too can only under-report. Distinct from the assisted family — it advertises `IAttestedBalanceAdapter`, not `IAssistedBalanceAdapter`, and has no assistant/delegatecall. The older `ASSISTANT_ROLE` agent-fed base Merkl once rode on was removed in #141.) (The Aave V3 Safety Module was previously listed as the documented exception per ADR 0002; ADR 0005 superseded that and made the SM adapter fully immutable.)

## Conventions you must respect

- **Adapters report balances, not values.** Every balance adapter returns `INAVCalculator.PositionBalance[]` with `amount` always **positive** and `isDebt` flagging debt vs. credit. NAVCalculator does the pricing and signing. See `src/balances/BALANCE_ADAPTERS.md` §2–§3.
- **`balanceAdapter` field is `address(this)`.** Always. It is the audit trail.
- **Adapters are immutable.** No `Ownable`, no admin functions, no upgrade. Constructor pins everything. There are **two** documented mutable-cache exceptions. (1) The **assisted balance-adapter family** ([ADR 0015](docs/decisions/0015-assisted-balance-adapter-family.md)): a per-account cache of position *coordinates only* (never amounts), values read live + ownership re-verified per read → **under-report only** (the contract-level half; the roles-modifier allow-list additionally makes the cache **complete** — see the dedicated bullet). It is **permissionless assistant-fed** ([ADR 0018](docs/decisions/0018-assistant-fed-assisted-balance-adapters.md); `IAssistedBalanceAdapter` marker, `msg.sender`-keyed, fed on-chain by a delegatecall `BalanceAdapterAssistant`) — see the dedicated bullet below. (2) The **attested balance-adapter family** ([ADR 0022](docs/decisions/0022-attested-balance-adapter-family.md); `IAttestedBalanceAdapter` marker — currently just `MerklRewardsAttestedBalanceAdapter`): caches a **proof-verified amount** (not coordinates), because Merkl allocations live off-chain and cannot be valued live; fed permissionlessly by an off-chain keeper that **upserts** proven `(account, token)` entries, with integrity resting on the on-chain merkle proof against the live root + stale-root→0 → **under-report only**. No assistant/delegatecall (distinct from the assisted family). See the intro paragraph. Any new mutable adapter requires a fresh ADR.
- **Typed position identity.** Every `PositionBalance` carries a 3-level protocol taxonomy — `bytes32 protocolBrand` (broadest, version-stripped grouping), `bytes32 protocolId` (broad ecosystem slug, e.g. `aave-v3`), and `bytes32 protocolSubId` (specific per-product slug, e.g. `aave-v3-lending`; the slug that selects the `positionId` decode schema) — plus `bytes positionId` (`abi.encode(...)` per protocol), `PositionKind positionKind` (`Wallet|Supplied|Borrowed|Collateral|Staking|Rewards|Fees`), a `bool isLocked` status flag, and an ephemeral `bytes32 positionInstanceId` (per-item NFT/request/ticket coordinate, excluded from the stable identity key). Slugs are kebab-case and the per-product ones are pluralised (`morpho-vaults`, `morpho-markets`, `balancer-v3-pools`, `gearbox-v3-markets`, `gearbox-v3-credit-accounts`, …). Full schema reference — slugs, positionId decode tables per protocol, reconciliation key, TypeScript examples: **`docs/howto/position-identity-schema.md`**. All constants in `src/utils/ProtocolIds.sol` and `src/utils/PositionKind.sol`.
- **Multi-leg `getAdapterPositions`.** Adapters whose underlying state has structurally distinct legs (lending supply vs. borrow, wallet LP vs. gauge-staked, vault assets vs. osToken debt) emit them as separate `PositionBalance` entries, each with the appropriate `PositionKind`. Staking principal = `Staking` (or `Supplied` pending migration). Accrued reward tokens = `Rewards`. Uncollected LP/protocol fees = `Fees`. Collateral (locked supply) = `Collateral`. Supply locked as collateral in Aave uses `Collateral`; freely withdrawable supply uses `Supplied`.
- **Meta-adapters for multi-instance protocols ([ADR 0010](docs/decisions/0010-meta-balance-adapters.md)).** For protocols with many fungible instances (Aave V3 instances, Morpho vaults/markets, Balancer V2/V3 pools+gauges, Curve pools+gauges, Convex (`ConvexCurveLPStakingMetaBalanceAdapter`), Uniswap V2/PancakeSwap V2 pairs, Uniswap V3/PancakeSwap V3 pools (`UniswapV3PoolsMetaBalanceAdapter` / `PancakeSwapV3PoolsMetaBalanceAdapter` — LP NFTs enumerated on-chain via the `ERC721Enumerable` NonfungiblePositionManager), Gearbox V3 markets + credit accounts (`GearboxV3MarketsMetaBalanceAdapter` / `GearboxV3CreditAccountsMetaBalanceAdapter`), Euler vaults, Compound V3 comets, Fluid fTokens/vaults, StakeWise V3 vaults), prefer **one immutable meta-adapter** (`…MetaBalanceAdapter`, extends abstract `MetaBalanceAdapter`/`IMetaBalanceAdapter`) over a contract per instance. Implement `_instancePositions(account, instance, filter)` + `_instanceAssets(instance)` plus the identity hooks `_protocolBrand()`/`_protocolId()`/`_protocolSubId()` (and override `_instancePositionId(instance)` whenever the positionId is not the default `abi.encode(_toAddress(instance))` — it is load-bearing, since `positionIds()` maps the governed instance set through it); build each leg via the shared `_leg(...)` helper and labels via `_labels(category, leaf)` (`LabelLib` provides the fail-open ERC20 `name()`/`symbol()` reads). Identity is derived **on-chain** from the `bytes32` instance coordinate (address widened, or raw bytes32 for Morpho marketIds / Balancer V2 poolIds). The active instance set is governed on `NAVCalculator` via `addMetaInstances`/`removeMetaInstances` (MANAGER-gated) — adding an instance is a config TX, not a deploy. Meta-adapters stay immutable (no admin functions). These supersede the matching per-instance adapters on mainnet. See `src/balances/BALANCE_ADAPTERS.md` §6.1.
- **Assisted adapters for externally-fed protocols ([ADR 0015](docs/decisions/0015-assisted-balance-adapter-family.md)).** The third adapter family, peer to plain and meta-adapters, for adapters that cannot derive a position from on-chain state alone and are fed position *coordinates* (never amounts). They are the immutability exception and must uphold the family invariant — cache coordinates only, value live on-chain, re-verify ownership per read → **under-report only**. **THE GUARANTEE HAS TWO HALVES and this repo enforces only the first.** *Contract level (here)* → **cannot over-report**. *Roles level (outside this repo)* → **cannot under-report either**, because the portfolio Safes' **roles-modifier permission set allows these protocol entries only through the assistant contracts — the direct protocol entrypoint is not in the allow-list** — so a position of these types **cannot be active without its coordinate having been fed**, making the cache **complete by construction, not merely conservative**. Do not try to read that half out of the code: `submit`/`remove` are permissionless and `msg.sender`-keyed and the assistant is the *canonical feeder*, not a gate, so these files alone show a permissionless cache with no completeness guarantee — the enforcement is in the **Safe's roles configuration**, which is not part of this repo. **Residual risk:** not an operator bypassing the assistant (not permitted), but **a change to the roles permission set adding a path that reaches the protocol without it**, after which the cache silently misses positions and **no tripwire in this repo would catch it** (every contract-level invariant still holds). Review roles-permission changes touching these protocols. The family is **permissionless assistant-fed** ([ADR 0018](docs/decisions/0018-assistant-fed-assisted-balance-adapters.md); `IAssistedBalanceAdapter` marker): no roles — `submit`/`remove` are `msg.sender`-keyed, so a caller only touches its own set. The canonical feeder is a stateless `BalanceAdapterAssistant` the owner Safe **delegatecalls** (so the adapter sees `msg.sender = Safe = owner`); a direct call reverts `NotDelegateCall`. Single shared base `AssistedBalanceAdapters/AssistedCoordCache`: one coordinate cache where each coordinate is an `abi.encode`d blob (uint256 members encode their id, StakeWise encodes its `(vault, ticket, timestamp)` tuple), deduped by `keccak256`, with the single-underlying-asset getter surface and a per-coordinate fail-open self-`staticcall` valuation fan-out. Members (each paired with a `…Assistant` in `AssistedBalanceAdapters/assistants/`): `NexusMutualStakingPoolsAssistedBalanceAdapter`, `StakeWiseV3ExitQueueAssistedBalanceAdapter`, `EtherFiWithdrawalQueueAssistedBalanceAdapter`. (Uniswap V3 / PancakeSwap V3 are meta-adapters, and Stader's withdrawal queue is a plain `BalanceAdapter` — none are assisted, because each is safely enumerable on-chain: the first two via `ERC721Enumerable`, Stader via `getRequestIdsByUser` (live-only, protocol-capped).) See `src/balances/BALANCE_ADAPTERS.md` §6.3.
- **Adapter addresses are per-chain (plain CREATE, not CREATE2).** The deploy script `04_DeployBalanceAdapters.s.sol` deploys each adapter with plain `new ...` (CREATE) broadcast from the deployer EOA via `_deployIfEnabled(...)`, so addresses are chain- and run-specific — read them from `script/config/deployments/<chainId>.json` (`.balanceAdapters.<name>`), don't assume they match across chains. (Constructor args for each adapter come from `script/config/contracts-deployment-config/balance-adapters/<chainId>.json` for plain adapters and `script/config/contracts-deployment-config/meta-balance-adapters/<chainId>.json` for meta adapters; `04` reads both.) (CREATE2 with the canonical deployer `0x4e59b44847b379578588920cA78FbF26c0B4956C` is used for the impl/library layer in `01`/`02`, not for adapters.) Current adapters also do NOT use a per-protocol factory contract — that pattern is **designed but not yet shipped** (see [ADR 0001](docs/decisions/0001-balance-adapter-factory-pattern.md), and `src/balances/factories/` does not exist as of `4def473`). Until the factory rollout lands, registration on `NAVCalculator` is done by `06_Configure.s.sol`, which **broadcasts directly from the deployer EOA** (`addBalanceAdapters(address[])` for plain adapters, `addMetaBalanceAdapter(address,bytes32[])` + `addMetaInstances`/`removeMetaInstances` for meta-adapters) — the deploy flow is EOA-only (no Safe executes deploy/config txs); the security-council Safe receives `DEFAULT_ADMIN_ROLE` at the end via `07_TransferAdminToSecurityCouncil.s.sol`. See `script/deploy/README.md`.
- **Per-protocol folder layout.** New balance protocols go under the matching family folder — `src/balances/BalanceAdapters/`, `src/balances/MetaBalanceAdapters/`, or `src/balances/AssistedBalanceAdapters/` (multi-file protocols keep a `<protocol>/` subdir inside the family folder) — with matching tests under `test/balances/<family>/`. The sibling factory file pattern from ADR 0001 is aspirational — don't add one until the factory framework is shipped.
- **Solidity pragma.** `pragma solidity ^0.8;` is the convention for new files (the bulk of `src/` uses it; some files — mostly the custom price feeds under `src/prices/protocols/` plus a couple of utils — still carry `^0.8.0`, and `src/deployment/Create2Deployer.sol` uses `^0.8.28`). The compiler is pinned in `foundry.toml` (`solc_version = "0.8.34"`, `evm_version = "cancun"`).
- **Morpho naming.** In any user-facing string (chain config `protocol` fields, docs, comments, comparison-report rendering), refer to the protocol as **`Morpho`**, not `Morpho Blue`. Even though Morpho Labs officially calls the lending primitive "Morpho Blue", we use the shorter form for consistency with the unbranded `MorphoVaultsMeta` / `MorphoMarketsMeta` adapter keys and to avoid the awkward "Morpho Blue Vault" combination that would otherwise arise. Solidity identifiers that reference the actual `Morpho` contract (e.g. the `MORPHO` immutable, or the `morpho` constructor-arg key holding `0xBBBB…cb`) are fine to leave — they're code, not display.
- **`NAV` casing.** The acronym is written **`NAV`** (all caps) in **type-level names** — contracts, interfaces, libraries, structs, enums, errors, constants: `NAVCalculator`, `INAVCalculator`, `NAVRegistryLib`, `struct NAV`, `VerboseNAV`, `NAV_DECIMALS`, `OnlyNAVCalculator`. In **mixedCase identifiers** — functions, parameters, local variables — treat it as a word (`Nav`): `getAccountNav`, `computeNav`, `getAccountNavVerbose`, `navCalculator`, `saltNavRegistryLib`. So `getAccountNav` (not `getAccountNAV`) is correct. One deliberate exception: the deploy salt-seed string and deployment-JSON key remain the literal `"NavRegistryLib"` so the library's deterministic CREATE2 address (pinned in `foundry.toml` / `LibraryPins.sol`) stays stable — renaming the seed would shift the address and force a pin regeneration.

## Testing expectations

- `forge build` and `forge test` must pass before you push. CI runs both.
- New adapters require **both** unit tests (mock-only) under `test/balances/<family>/<Adapter>.t.sol` *and* a fork test under `test/balances/<family>/fork/<Adapter>.fork.t.sol` against a real holder at a pinned block.
- Fork tests use `FOUNDRY_PROFILE=slow forge test --match-path "test/**/fork/*.sol"` to throttle RPC.
- Don't mock the balance adapter in NAVCalculator integration tests — assert against deployed adapter instances on a fork.
- Integration tests in `test/integration/` are JSON-driven (`test/integration/accounts.json`). Don't edit fork blocks or expected NAVs directly in the per-chain `*.t.sol` files — run `script/test/refresh-integration-snapshot.sh` (see `docs/howto/refresh-integration-test-blocks.md`).

## Project rules (from MEMORY.md)

- **The user merges PRs.** When CI is green, monitor and report. Do not run `gh pr merge` yourself.
- **Don't push to `main`.** Always work on a feature branch and open a PR.
- **Pre-existing local changes are not yours to commit.** If `git status` shows files you did not touch (e.g., `foundry.toml`, scripts), leave them alone unless the user asks.
