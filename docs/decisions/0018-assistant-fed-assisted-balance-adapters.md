# 0018 — Permissionless assistant-fed assisted balance-adapter family

## Status

accepted (supersedes the per-protocol drafts once numbered 0018/0019/0020 for Nexus, StakeWise, ether.fi, Stader — folded into this single family ADR)

## Context

ADR [0015](0015-assisted-balance-adapter-family.md) named the **assisted** family: adapters that cannot derive a position from on-chain state alone and must be fed the missing *coordinates* by a trusted party, upholding the invariant **cache coordinates only (never amounts), value every read live on-chain, re-verify ownership per read → under-report only**. Its members were fed by an **off-chain agent** holding `ASSISTANT_ROLE`, which submitted the full candidate set (`submitTokenIds`) for many accounts.

A second feeding pattern then recurred for on-chain, per-position flows — Nexus Mutual staking, StakeWise V3 exit queue, ether.fi and Stader withdrawal queues. Here the position is created/destroyed by a transaction the position owner itself sends, so the coordinate can be fed **on-chain, atomically, in that same transaction** — no off-chain agent, no staleness window. Four PRs each built this independently and diverged gratuitously: three trust models (`SUBMITTER_ROLE` / `WRAPPER_ROLE` / permissionless), two delegatecall-guard error names (`OnlyDelegateCall` / `NotDelegateCall`), and duplicated foundation contracts + ADRs. They could not merge side by side.

## Decision

Introduce a **permissionless, assistant-fed** variant of the assisted family, with one shared foundation. The two most recent implementations converged on it and it is the canonical model going forward.

**Trust model — permissionless, `msg.sender`-keyed.** The adapter's `submit`/`remove` take **no `account` argument and no role**: they derive the account from `msg.sender`, so a caller can only ever mutate its OWN cached set. The invariant of ADR 0015 is preserved by live re-verification alone (values read on-chain, ownership re-checked per read), so a role adds nothing — a faulty feeder can only under-report regardless. This drops all post-deploy role grants.

**Feeder — a delegatecall action assistant.** The canonical feeder is a stateless assistant (`src/balances/AssistedBalanceAdapters/assistants/`) the owner Safe `delegatecall`s. Under `delegatecall` `address(this)` is the Safe, so the protocol sees `msg.sender = Safe` (the position owner) and the adapter's `msg.sender`-keyed cache records against that same Safe. No custody, no asset-forwarding, no role. An assistant's own deployed address is pinned at construction (`SELF`); a direct (non-delegatecall) call is rejected fail-loud with the canonical `NotDelegateCall` (`src/errors.sol`).

**Shared foundation.**
- **`IAssistedBalanceAdapter`**: minimal marker `is IBalanceAdapter` exposing only `clearAccount()` (self-service GC). No `IAccessControl`, no role getter. (A prior `ASSISTANT_ROLE` agent-fed marker/base — `IAssistantFedBalanceAdapter` / `AssistantFedBalanceAdapter`, used only by the Merkl rewards adapter — has been removed pending a rewrite of Merkl; it is retrievable from git history. The assisted family is now solely this permissionless assistant-fed variant.)
- **`AssistedCoordCache`** — the **single** cache base. A coordinate is an opaque `bytes` blob, so one cache serves every member regardless of shape: a bare `uint256` NFT tokenId / requestId (`abi.encode(id)`) or a tuple (StakeWise `abi.encode(vault, positionTicket, timestamp)`). Provides the `msg.sender`-keyed `submit`/`remove`/`clearAccount` (blobs deduped by `keccak256`, cap + fail-loud `CoordinateCacheFull`/`CoordinateNotOwned`), the single-underlying-asset `IBalanceAdapter` getter surface, and a per-coordinate fail-open self-`staticcall` valuation fan-out (so a revert-prone valuation like Nexus's `StakingViewer.getTokens` isolates to that one coordinate). Concrete adapters implement `_validateCoord` / `_removable` / `_valueCoord` / `_coordId` / `_maxCoords` / `_maxLegsPerCoord` and expose a typed `submit`/`remove` that `abi.encode`s their coordinate. (An earlier draft split this into a `uint256`-only `AssistedNftIdCache` + `AssistedNftIdValuation` plus a tuple `AssistedCoordCache`; collapsed to one base since a `bytes` coordinate subsumes both.)
- **`IBalanceAdapterAssistant`** / **`BalanceAdapterAssistant`** — assistant marker + abstract base contributing `SELF`, `ADAPTER`, and the `onlyDelegateCall` guard.

## Consequences

- **Members** (all rebased onto the foundation): `NexusMutualStakingPoolsAssistedBalanceAdapter`, `StakeWiseV3ExitQueueAssistedBalanceAdapter`, `EtherFiWithdrawalQueueAssistedBalanceAdapter`, each paired with a `…Assistant`. Each shrinks to protocol-specifics (the per-id/coord valuation, the `_ownerOf`, the labels, the forward calls).
- **Not a member: Stader.** Stader's withdrawal queue was briefly modeled as an assisted member but reverted to a plain `BalanceAdapter`: Stader exposes `getRequestIdsByUser(account)` — a live-only (claim-pruned, swap-and-pop), protocol-capped (`maxNonRedeemedUserRequestCount`) on-chain enumeration — so no feeder is needed. The griefing that motivates the assisted model elsewhere (a third party injecting entries) is present but self-defeating here: `requestWithdraw(_ethXAmount, _owner)` burns the *caller's* ETHx into a request claimable *only by `_owner`*, so an attacker can only donate real, claimable value to the account (equivalent to an airdrop), never inflate it for profit or recover it; the plain adapter bounds the read at the protocol's own cap.
- Adding the next assistant-fed protocol is a small adapter + assistant extending the bases — no re-derivation of the cache, valuation fan-out, delegatecall guard, or trust model.
- **EOA depositors cannot use an assistant** (an EOA cannot `delegatecall`); the intended feeders are Safe/Avatar accounts, gated at the Safe/Zodiac layer.
- **The roles-modifier allow-list makes the cache COMPLETE, not just conservative — and this is the strongest property in the family.** The permissionless `msg.sender`-keyed model above argues that "a role adds nothing, since a faulty feeder can only under-report regardless". True, but it understates what production actually guarantees: **the portfolio Safes' roles-modifier permission set allows these protocol entries only *through the assistant contracts*; the direct protocol entrypoint is not in the allow-list.** So a position of these types **cannot be active without its coordinate having been fed** — the un-fed position cannot come into existence. The two halves are complementary: *contract level* (this repo) → **cannot over-report**; *roles level* (outside this repo) → **cannot under-report either**.
  - **Enforcement is NOT in this repository**, and the code reads the opposite way, so the pointer matters: `AssistedCoordCache`'s mutators are permissionless and the assistant is *the canonical feeder*, not a gate. A reader of those files alone sees a permissionless cache with no completeness guarantee. The guarantee lives in the **Safe's roles configuration**, outside this repo.
  - **Residual risk:** not that an operator bypasses the assistant (not permitted), but that **a change to the roles permission set introduces a path reaching the protocol without the assistant.** The cache would then silently miss positions with **no tripwire in this repo** — all contract-level invariants would still hold. Review roles-permission changes touching these protocols.
  - See [ADR 0015](0015-assisted-balance-adapter-family.md) and `src/balances/AssistedBalanceAdapters/README.md` §5.0.
- The former `ASSISTANT_ROLE` agent-fed base and its sole member (Merkl) were removed here; re-homing Merkl onto this permissionless family (or a fresh variant) is a separate follow-up.
- Supersedes the per-protocol framing that was drafted separately for Nexus/StakeWise/ether.fi/Stader; ADRs 0014/0015 still stand (this refines 0015's feeding model, it does not replace the family or its invariant).
