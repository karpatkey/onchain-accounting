# 0019 — StakeWise V3 exit-queue wrapper-fed adapter (delegatecall feeder, self-submit)

Status: accepted

## Context

StakeWise V3 exit-queue positions are not enumerable: a position is identified only by a `positionTicket` emitted in `ExitQueueEntered`, with no owner→tickets view, so a pure-view adapter cannot discover them. ADR [0014](0014-agent-fed-cache-adapters-for-exit-queues.md) surfaces them to NAV with `StakeWiseV3ExitQueueAssistedBalanceAdapter`, fed by an **off-chain** `ASSISTANT_ROLE` agent that scrapes the events and submits `(vault, positionTicket, timestamp)` tuples — leaving a staleness window between the on-chain enter/exit and the agent's next submission.

ADR [0018](0018-wrapper-fed-assisted-balance-adapters.md) added a **wrapper-fed** variant to the assisted family (ADR [0015](0015-assisted-balance-adapter-family.md)): an on-chain wrapper holding `WRAPPER_ROLE` pushes/pops coordinates atomically as it forwards deposits/withdrawals. Its first member (Nexus Mutual staking) uses a **normally-called** wrapper: it `transferFrom`s the depositor's (transferable) NXM, forwards to the pool, and Nexus's **permissionless** `withdraw` routes funds to the NFT owner — so one shared wrapper contract can hold `WRAPPER_ROLE` and act for every depositor.

**StakeWise does not fit that shape.** Two protocol constraints break the normally-called model:

1. `claimExitedAssets(positionTicket, timestamp, exitQueueIndex)` is keyed on `msg.sender` — only the address that was the `receiver` at `enterExitQueue` time can claim. A shared wrapper called normally would be `msg.sender`, so only it could claim; the depositor could not.
2. StakeWise V3 vault shares are internal, non-transferable balances — a wrapper cannot `transferFrom` a depositor's shares to enter the queue on its behalf.

## Decision

Feed the StakeWise exit-queue adapter on-chain, through a **permissionless delegatecall** wrapper, with **no access control on either contract** — safety comes entirely from `msg.sender`-scoping plus the adapter's live re-validation. Same family invariant as ADR 0015/0018 (cache coordinates only, value live, re-verify ownership per read → a caller can only under-report).

- **`StakeWiseV3ExitQueueAssistedBalanceAdapter`** (`src/balances/AssistedBalanceAdapters/`) — **replaces** the ADR-0014 agent-fed adapter of the same name (which is removed; the `ASSISTANT_ROLE`/`submitPositions` off-chain-agent surface is gone). No roles, no admin: `submit(vault, positionTicket, timestamp)` / `remove(...)` derive the account from `msg.sender`, fed one ticket at a time, so a caller can only ever touch its OWN tracked set. `submit` is fail-loud: `InvalidExitPosition` if the vault isn't StakeWise-registered, `NotExitPositionOwner` if the ticket doesn't belong to the caller (the on-chain proxy `calculateExitedAssets(caller, …)` is zero), `PositionCacheFull` past `MAX_POSITIONS`. `remove` is fail-loud too — it reverts `PositionNotTracked` unless the `(vault, positionTicket, timestamp)` tuple is in the caller's set (the ticket must belong to the caller). Every read re-validates live via `calculateExitedAssets(account, …)`. The cache + valuation are unchanged from the prior agent-fed adapter (per-ticket claimable/locked split on `EXIT_CLAIM_DELAY`, `positionId = abi.encode(vault)`, `positionInstanceId = bytes32(positionTicket)`, `["Exit Queue", "<receiptSymbol>"]` labels). A self-service `clearAccount()` GCs the caller's own set. Kept as a **single self-contained contract** for now; may be abstracted into a shared base in a follow-up.
- **`StakeWiseV3ExitQueueWrapper`** (`src/balances/wrappers/`) — a **permissionless delegatecall action** the depositor Safe delegatecalls. Because it runs in the Safe's context, `address(this)` is the Safe: the vault sees `msg.sender = Safe`, the exit position is owned by the Safe (`receiver` forced to `address(this)`), the Safe can later claim, and claimed assets are paid directly to it — no custody. `enterExitQueue(vault, shares)` calls the vault then calls `adapter.submit(vault, ticket, block.timestamp)` **directly** — that call carries `msg.sender = the Safe`, so the adapter tracks the Safe's own position; `claimExitedAssets(vault, positionTicket, timestamp, exitQueueIndex)` claims then `adapter.remove(...)`. Signatures mirror the vault's, with `vault` prepended. It holds no roles; **which Safe may run it is governed by that Safe's own permission system** (e.g. a Zodiac Roles module). It performs no storage writes (delegatecall runs in Safe storage) and enforces `onlyDelegateCall` (reverts `NotDelegateCall` if called directly — detected by `address(this) == SELF`), since a direct call could not act as the Safe.

**Why no access control is safe.** The adapter self-scopes by `msg.sender`, so nobody can register or (crucially) deregister another account's positions — the third-party `remove`-griefing that access control would otherwise guard against is impossible by construction. Fabrication is impossible because the adapter re-validates every ticket live on-chain against the account. A stray registration by a random address only affects that address's own (NAV-unqueried) set, bounded by `MAX_POSITIONS`. So roles/admin add nothing here; removing them shrinks the trust surface to zero.

**Relationship to `WrapperFedBalanceAdapter` (ADR 0018).** Same family and invariant, but this adapter is fully permissionless rather than gated by a single-wrapper `WRAPPER_ROLE`. The StakeWise-specific driver: claim is keyed on `msg.sender` and vault shares are non-transferable, so the wrapper must run in the Safe's context (delegatecall) — and once the adapter self-scopes by `msg.sender`, the `WRAPPER_ROLE`/admin machinery (and the self-call indirection an earlier revision used to satisfy it) become unnecessary.

## Consequences

- StakeWise exit-queue tracking moves to an on-chain, atomically-maintained path for managed Safes. The ADR-0014 agent-fed StakeWise adapter is **removed and replaced** by this wrapper-fed adapter (same contract name, `StakeWiseV3ExitQueueAssistedBalanceAdapter`). ADR 0014 still governs its ether.fi sibling.
- Neither contract has roles or an admin. Access to *enter/exit the queue* is delegated to each Safe's own permission system; access to *track/untrack* is inherently self-scoped (`msg.sender`). Every read re-verifies ownership against `receiver = account`, so a faulty caller can only under-report.
- The wrapper is a documented immutability exception (assisted family). Its `enterExitQueue`/`claimExitedAssets` are **delegatecall-only** (`onlyDelegateCall`); a direct call reverts `NotDelegateCall`.
- Deploy-script / config-JSON wiring is deferred to a follow-up (as for ADR 0018's first member).
- This extends ADR 0015/0018 with a permissionless delegatecall feeder topology, and supersedes the StakeWise V3 portion of ADR 0014 (its ether.fi portion is unaffected).
