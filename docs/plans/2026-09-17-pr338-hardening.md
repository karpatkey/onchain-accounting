# Hardening plan for PR #338 — correct-by-construction, not correct-by-review

**Question answered:** what must change so these contracts stop generating a new defect from each
review round's fixes. **Date:** 2026-09-17. **Produced by:** one Fable planning agent, briefed with
the measured constraints (95-byte NAVCalculator margin, library-vs-contract byte asymmetry, the
six-defect chain, and the approaches already measured and rejected).

## Diagnosis

The invariant that matters — *every token has exactly one live reporter; a coordinate is governed by
at most one adapter; a registered asset is default-included iff unclaimed* — **is not stored
anywhere**. It is the emergent product of three independently mutable stores:

- `ERC20DefaultBalanceAdapter._supportedAssets` (adapter storage)
- `Balances._metaInstances` (NAV proxy storage)
- `Balances._isAdapterRegistered` / `_globalAdapters` (decides live vs dormant residue)

Because it is nowhere evaluable, it is maintained by requiring **every mutation path to perform the
correct compensating writes on the other stores**. There are now **seven** such writers. Every fix in
rounds 4–6 was the discovery that one writer was missing a compensating write — and each fix *adds
another writer*, so the next reviewer must re-derive the whole protocol from prose. The defect
generator is the architecture, not the authors.

Three supporting properties:

- **Guards quantify over the operation's input, not the resulting state.** `_appendInstances` loops
  the incoming batch, so an empty batch proves the post-state property vacuously.
- **Prose is the load-bearing spec and has no checker.** `NAVRegistryLib.sol` is 607 lines, ~150 of
  them code; the comments *are* the invariant store the types lack. Hence ~40% of findings being
  false comments, every one false in the reassuring direction.
- **Scripts hold the protocol's transition logic and have no test harness.** Defects 1–3 all live in
  `RealignHeartbeats.s.sol`, first executed for real in production simulation.

## VERIFIED against the code (2026-09-17)

The plan's sharpest claim — that the compensating-write scheme is **still open right now** — checks out:

- `NAVCalculator.sol:371-375` `includeAssetInDefaultAdapter` calls `addSupportedAsset` with **no
  claim check**. One MANAGER transaction re-includes a token a meta adapter governs.
- `NAVCalculator.sol:181` `registerAsset` includes **unconditionally**. Claim a not-yet-registered
  token as a meta instance, then register it → governed *and* default-included.
- `test/nav/NAVCalculator.handler.t.sol` drives **zero** meta-instance operations — the invariant
  fuzzer does not touch the surface where five of six defects live.

## The changes, ranked

**S1 — single-writer ownership.** `mapping(bytes32 => address) _claimant` in `Balances`; funnel every
`_metaInstances` write through `_claim` / `_release`; `_registerAdapter` wipes any residual set.
Makes *unrepresentable*: dual claim, residue revival, governed-and-included. Deletes the nested scans
— and with them the entire "guard loops over the wrong set" shape. Closes six open items at once.

**S2 — retire dead surface while the pins are already moving.** `extractUniqueAssets` and
`_metaInstanceTotal` are both documented-as-dead-but-kept-for-the-pin; this PR moves the pin.

**S3 — extract script predicates; resolve the real signer.** Pure functions with full truth-table
tests; replace the approximate signer check with `vm.readCallers()` after `startBroadcast()`, making
"right role, wrong address" unwritable.

**S4 — prove the wallet-yield family before it is ever registered.** 17 unit + 17 fork parity tests
(equality, not tolerance), a family-completeness meta-test so "0 of 17" is a red build, and a
per-chain probe that the live default adapter answers `isSupportedByDefault`.

**S5 — one owner for the raw-staticcall idiom, enforced by CI lint.**

**S6 — shrink the load-bearing prose; pin measured claims to tests; ban `file:line` refs in comments.**

## Test strategy

- **T1** stateful invariant fuzzing over the *whole* registry surface with I1 (no coordinate has two
  claimants), I2 (registered asset: included XOR claimed), I3 (NAV equals the count of distinct
  expected reporters — the over-report oracle).
- **T2** truth-table tests for every extracted predicate; defects 2 and 3 are each a wrong cell.
- **T3** mutation sweep scoped to the diff — the one mechanical detector of a vacuous guard.
- **T4** every new `revert` ships with a test that makes it fire.
- **T5** script harness tests once plan/verify are extracted.
- **T6** the 17 fork/parity tests plus the completeness meta-test.

The false-prose class is not Foundry-testable; it shrinks structurally, because S1 deletes the
comments that carry the invariants.

## Order

1. T1 handler extension + I1–I3 **against current code** — expected to catch the two open holes. This
   is the plan's falsifiable prediction.
2. S1, with T1 green on top; measure `forge build --sizes` before and after.
3. S2. 4. S3 + T2 + T5. 5. Backfill script round-tripping live coordinates through the new primitives.

**Before any of the 17 adapters is registered anywhere:** S4 in full, plus the `04` dispatch branch
and chain config — an adapter family should not gain a deploy path before it has a test path.

**Deferrable:** T3 automation, S5 lint, S6 CI greps.

## Falsifiers

- Byte estimates are the soft spot; history shows intuition fails here (a −148 B selector, a +484 B
  extraction). Prototype and measure.
- The backfill is itself a new transition of the defect-generating kind; fork-simulate on all 7
  chains and require a zero NAV delta.
- **Mutation-test T1 itself:** re-introduce defects 5 and 6 and require I1–I3 to go red. If they stay
  green, the invariant suite is decorative and the plan's central claim fails.
- The diagnosis is falsified if a later round finds a real defect inside the S1 primitive surface that
  is neither a script predicate nor prose.
