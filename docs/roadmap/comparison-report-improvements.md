## Tier 2 — moderate cost, nice quality-of-life

### 1. Etherscan / explorer links on addresses

Every truncated address (`0xa3931d71…`, `0xfbb81382…`, etc.) is currently unclickable. Inline-link them to the appropriate per-chain explorer:

- mainnet → `https://etherscan.io/address/0x…`
- arbitrum → `https://arbiscan.io/address/0x…`
- base → `https://basescan.org/address/0x…`
- optimism → `https://optimistic.etherscan.io/address/0x…`
- gnosis → `https://gnosisscan.io/address/0x…`

Per-chain explorer URLs already exist in `script/config/chains/<id>.json.explorer`. Map them through `chains_cfg[cid]['explorer']` when rendering. Pure markdown link, sweep through `build_item_label`, `build_debank_proto_detail`, the wallet-table address column, and the untracked footer.

**Effort:** ~30 min. **Risk:** none — pure rendering change.

### 2. Per-problem-account drift breakdown line

Under each ⚠ chain header, add a one-liner explaining where the residual gap comes from. Example:

```
**NAV: $17.551M | Debank filtered: $18.074M | Drift: -2.90% ⚠️**
**Residual breakdown:** $525K Uni V3 WETH/COW LP (Debank counts under uniswap3; NAV pool disabled — depends on COW price feed PR).
```

Could read from `chains.<id>.$untracked_by_design` (free-form prose) or be hard-wired per known case. Hard-wired is simpler — there are very few problem-account cases at any given time. **Effort:** ~30 min.

### 3. Vertical separator between Debank columns and NAV columns

**Partially addressed by `b34898c`'s rename** (every column now has a `Debank` or `NAV` prefix; per-section italic legend explains the side). What's still missing is a real visual divider in the rendered HTML so the eye groups columns 1–6 (Debank) and 7–9 (NAV) without reading every header. Markdown viewers vary on whether `||` renders as a separator; one safe option is two side-by-side sub-tables per protocol with a `↔` between them. Lower priority now that the prefix-naming did most of the work. **Effort:** 1–2 hours.

### 4. Hide protocol rows with sub-$0.01 totals

Today the report emits rows for protocols with `proto_net_usd(p) < $0.01` (e.g. `Compound V3 | compound3 | $0.0014` on ACCOUNT_9 mainnet, with all-dashes for item/NAV columns). Adds noise. Filter the `covered_protos` partition with the same `>= 0.01` threshold the items use.

```python
covered_protos = [p for p in chain_protos if p.get("_short_id", "") in supported_ids and abs(proto_net_usd(p)) >= 0.01]
```

Plus apply the same threshold to the untracked-by-design footer entries (already partial — items are filtered, but the protocol-level total isn't).

**Effort:** 5 min. **Risk:** none.

## Tier 3 — bigger lift, lower payoff

### 5. Stacked sub-rows for multi-token Debank items

When a Debank position has 3+ tokens, the cell becomes hard to read:

```
"supply WETH 0.001364 + supply ETH 0.015757 + reward WETH 0.000907 + reward ETH 0.000925"
```

Could become a tree:

```
Aave V3 — Lending  $42.85
  └ supply WETH 0.005 → $11.87
  └ supply wstETH 0.06 → $174.20
  └ borrow WETH -0.06 → -$139.54
```

Bigger refactor — one extra row per token per item. Per-row matching against NAV gets more complex. **Effort:** 2–3 hours. **Risk:** moderate (touches the matching algorithm).

> Aside: `b34898c` fixed a related bug where Stage 2 of the matcher was claiming single-position protocol groups for items that already had a Stage-1 1:1 match — surfacing as phantom `—` rows on Morpho-shaped protocols. The Stage 2 fallback now requires `len(group) >= 2` (i.e., it only fires for genuine LP-pool / reward-bundle cases). The stacked-sub-rows item above is a separate UX improvement, not blocked on a matcher fix.

### 6. Color-coded drift heat scale

Current ✅/⚠ binary is fine; could go further with a percentage-shaded heat. GitHub renders shields.io badges, plus markdown supports inline HTML `<span style="…">` on some viewers. Probably not worth it. **Effort:** 1 hour. **Payoff:** marginal.

### 7. Anchor links / TOC

Long doc, no TOC. Top of file gets clickable `[ACCOUNT_1](#account_1)` etc. Markdown auto-generates anchors from headers; just add a navigation block at top. **Effort:** 15 min. **Payoff:** moderate (with the new drift-summary table much of this is redundant — clicking the account name in the summary could anchor-jump).

Better implementation: make the `Account` cell in the drift summary a clickable link to the per-account section.

```markdown
| [ACCOUNT_1](#account_1) | mainnet | $180.83 | $180.10 | +0.41% | ✅ |
```

**Effort:** 5 min instead of 15.

### 8. Per-account metadata header

Above each `## ACCOUNT_X`, a 2-3 line summary block:

- Address (with link)
- Total NAV across all enabled chains (sum)
- Active chains: list (skipping zero ones)
- Link to a user-facing dashboard if you have one

Reduces scrolling around. **Effort:** 30 min.

## Accuracy items (separate from layout)

### 9. ACCOUNT_9 wallet ETH not matching NAV

Currently shows:

```
| ETH | 56.546754 | $2,345.65 | $132,638.89 | `eth` | — | — | — | — |
```

NAV columns are dashes — meaning NAV's wallet sweep doesn't surface ACCOUNT_9's 56 ETH. This is suspicious because ETH IS in `_symbolsForChain(1)`. Plausible causes:

- The fork-block snapshot has a different ETH balance than the current Debank fetch (temporal)
- NAV's wallet sweep skipped ETH for some reason
- nav-positions-1.json is stale (ACCOUNT_9 used to have less ETH at the snapshot block)

The integration test passes (asserts NAV against `navUsd8dp`, not against Debank), so this is informational. But worth investigating: rerun `script/test/refresh-integration-snapshot.sh`, then check whether the ETH wallet shows up in `nav-positions-1.json[ACCOUNT_9]`.

### 10. Untracked-by-design Detail column verbosity

Today the footer's "Detail" column for protocols pipes through `build_debank_proto_detail(p)` which produces strings like:

```
supply: COW 7.9090M ($1.422M) → **$1.422M**
```

That's fine for protocols with one item; gets messy for multi-item ones. Could drop the inline detail and keep just `Source / Type / $ value`, with detail available on Debank by clicking the address. **Effort:** 5 min.
